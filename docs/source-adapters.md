# Live adapters

The collector reads a bounded registry of RSS/Atom feeds and public HTML news indexes. It does not search the whole web, bypass logins/paywalls, run site JavaScript, or obtain licensed race/form data. The hosted workflow rotates through up to two sources and two items per source per run. Add a reviewed source in Settings; custom HTML indexes need an article path prefix. Racing Queensland was enabled after its access check; other registry entries stay disabled until reviewed.

Requests use HTTPS, exact registered hosts, public DNS addresses pinned to their sockets, redirect revalidation, robots rules, a 15-second deadline and a 2 MB response limit. A robots 404 means no published robots rules; other robots errors stop that source. Access failures, unreadable pages and empty indexes are reported. The source's timestamp and retrieval time remain separate; unknown publication dates are explicitly flagged. Private archives retain the original page/feed entry and cleaned text. Publisher image references are recorded as unknown and are excluded from publication until independently cleared.

Live smoke test on 9 September 2026: Racing Queensland's robots.txt returned HTTP 200 with a sitemap declaration and no crawl restrictions. The Thoroughbred index successfully yielded two actual article pages, with zero collection errors:

- [Amanda Benson honours late jockey in QOTT award win](https://www.racingqueensland.com.au/news/2026/09-september/amanda-benson-qott-acknowledged-retrainer-of-the-year)
- [Nunn eyeing more Queensland success before Tassie return](https://www.racingqueensland.com.au/news/2026/09-september/nunn-eyeing-more-queensland-success-before-tassie-return)

The smoke test did not persist or enable sources, call AI, or publish anything. Navigation and category links were excluded; a regression test covers this. This is an access test, not permission to republish protected articles. Racing NSW's robots endpoint returned 404; its feed still needs an end-to-end access check. Racing Victoria's news index appears to rely on JavaScript and may require an approved feed/API adapter.

AI research uses a current `NEWSROOM_MODEL` in `provider/model` format, authenticated with either `AI_GATEWAY_API_KEY` or Vercel OIDC. On Vercel, `@vercel/oidc` obtains the current invocation's token before each request; no static AI key is required. A configured API key takes precedence. Local OIDC tokens from `vercel env pull` expire and must be refreshed. Configuration readiness does not prove that account credits are available: HTTP 402/429 and authentication failures remain visible and never trigger mock results or purchases. The public Gateway catalog confirmed `openai/gpt-4.1-mini` is available on 9 September 2026 at $0.40 per million input tokens and $1.60 per million output tokens. Its non-reasoning operation fits this first version's short deadlines; the model remains configurable.

Six separate discipline prompts return schema-validated findings. Each request reads at most five 4,500-character source excerpts and uses a 14-second timeout, including credential lookup. Unsupported quotes and unknown source IDs are rejected. Editorial agents can select and order exact verified Hub statements; this first version does not trust free-form model paraphrases as verified prose. Per-request OIDC rotation, API-key precedence and missing-token errors are covered by adapter tests.

Deployment diagnostic: a minimal OIDC-authenticated request returned HTTP 403 with `customer_verification_required`: Vercel requires a valid credit card on this AI Gateway account to unlock its free credits. No private source material was sent, no token was logged, and no card or credits were added. The owner must complete that account verification in Vercel before live AI can operate. An idempotent provider preflight now checks access once before research; authentication, credit and access failures suppress further model requests for that run. Provider error bodies are mapped to fixed operational messages instead of exposing arbitrary upstream text.

Reader email imports preserve original RFC 822 bytes in base64, headers and attachment metadata. Email claims always enter as unverified leads, with correction priority where detected. Attachments are not executed or treated as verified images. The inbound endpoint validates the raw Svix-signed Resend event and matches its recipient against `NEWSROOM_INBOUND_ADDRESS` before fetching content. Unrelated mail is acknowledged and ignored. It retrieves matching mail from its signed public CloudFront/Resend URL without forwarding API credentials. Missing raw originals, oversized mail and unexpected hosts fail visibly. Live delivery requires `RESEND_API_KEY`, `RESEND_WEBHOOK_SECRET`, the dedicated receiving address and Gmail forwarding; it is not connected. `.eml` import, signature rejection and recipient-isolation tests passed.

`NEWSROOM_CONTACT_EMAIL` is the reader communication address. `RESEND_FROM_EMAIL` is reserved for a separately verified sending domain. Neither the personal contact mailbox nor Vercel account email is silently used to impersonate a verified sender. No outbound messages are sent by these adapters.
